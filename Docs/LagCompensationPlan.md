# M3: 서버 리와인드 기반 Hitscan Lag Compensation 구현 및 이동 표적 검증

## 현재 상태

구조 분리와 레거시 정리는 완료했다. M3의 Lag Compensation은 아직 구현되어 있지 않다. 현재 `WeaponFireComponent::ServerFire`는 조준 방향과 발사 ID를 받아 서버의 현재 카메라 위치에서 현재 월드를 trace한다. 발사 시각 검증, 과거 위치 기록, 보간과 리와인드 판정은 없다. `ShotId`는 계측 응답을 연결하는 용도다.

## 구현 순서

1. **서버 위치 이력 분리**
   - Character에 `RewindHistoryComponent`를 부착한다. 서버만 시각·위치·캡슐 크기·생존 상태·생명 ID를 제한 길이 ring buffer에 기록한다.
   - 최대 보정 시간, 기록 주기, 시간 오차 허용값과 기능 on/off는 별도 설정 데이터 에셋 한 곳에서 관리한다.
   - 초기 범위는 현재 충돌 모델과 동일한 캡슐 hitscan이다. 본 단위 hitbox와 headshot은 후속 범위다.
2. **발사 요청의 시각·순서 검증**
   - 발사 명령에 ShotId, 생명 ID, 서버 시계로 변환한 발사 시각을 포함한다. M2 Prediction/Reconciliation도 같은 명령 형식을 사용하도록 맞춘다.
   - 서버가 시계 오차, 최대 리와인드 구간, 미래 시각, 중복·역순 명령과 이전 생명 ID를 검사한다. 허용 구간을 벗어난 요청은 명시적으로 거부한다.
   - 발사 속도·탄약·재장전·사망 검사는 서버 권한으로 유지한다. 클라이언트가 피해량·명중 대상·발사 원점을 결정하지 않는다.
3. **무기 아래 판정 컴포넌트 분리**
   - `WeaponHitValidationComponent`가 현재 판정과 리와인드 판정을 선택한다. Fire는 명령 처리와 발사 상태, Ammo는 탄약과 재장전을 계속 담당한다.
   - 검증된 발사 시각의 서버 이력에서 발사 원점을 구하고, 대상의 표시 시각 정책에 따라 과거 캡슐을 보간해 가장 가까운 명중을 계산한다. 대상 표시 지연 보정량은 서버 설정으로 제한한다.
   - 살아 있는 Actor의 위치·충돌을 일시 이동시키는 대신 이력 기반 교차 계산 또는 별도 query proxy를 사용한다. 정적 월드의 차폐 trace와 과거 표적 판정을 함께 비교한다.
   - 초기 동적 차폐물은 현재 서버 월드 기준으로 처리한다고 명시한다. 동적 차폐 이력까지 보정하려면 별도 정책과 이력을 추가한다.
   - 실제 피해 적용 시 현재 서버의 대상·생명 ID·팀·사망·경기 종료 상태를 다시 검사한다. 리스폰 전 이력으로 새 Pawn에 피해가 적용되지 않게 한다.
4. **보정 효과와 회귀 검증**
   - 이력 보간, 구간 경계, 버퍼 순환, 미래/오래된 시각, 중복 발사, 사망·리스폰·접속 종료를 자동화 테스트로 검사한다.
   - 이동 표적 시나리오에서 보정 on/off와 PktLag=0/50/100/150/200ms를 비교한다. 단방향 설정값과 실제 관측 RTT를 구분해 기록한다.
   - 동일한 이동 경로·발사 일정·spread seed를 사용하고, 기대 명중과 서버 결과를 비교해 정당한 명중·오판정·누락과 판정 지연 P50/P95를 기록한다.
   - 먼저 loss/jitter=0 조건을 검증한 뒤 손실·지터와 동적 차폐 정책을 별도 실험으로 확장한다.

## 완료 기준

허용된 과거 시점에서 이동 표적 판정이 재현되고, 비정상 요청·이전 생명 이력은 피해를 만들지 않아야 한다. 기능 off에서 현재 Baseline 동작과 기존 회귀 테스트가 유지되어야 한다. 동일 시나리오의 on/off 원시 표본과 집계 결과를 제출한다. 람다 없이 이름 있는 함수와 컴포넌트 경계로 구현한다.
