# 플레이 중 실시간 실험 지표

Development Editor와 Development Game에서 오른쪽 **실시간 실험 지표** HUD로 실험 조건을 바꾸고 현재·평균·최소·최대를 확인한다. 표시 문구는 한글이며 나눔스퀘어 네오 일반체·굵은체를 프로젝트 FontFace 에셋으로 포함한다. 서버에 접속한 어느 클라이언트에서든 조건을 요청할 수 있고, 서버가 승인한 조건은 같은 세션 전체에 적용된다. 각 창에 표시되는 측정치는 그 창을 소유한 로컬 플레이어 기준이다.

## 조작

| 입력 | 동작 |
|---|---|
| Tab | 오른쪽 상세 통계·그래프를 0.25초 슬라이드로 열기/닫기. 기본 상태는 현재 왕복 지연·프레임률·리와인드·설정 지연만 보이는 요약 카드다. |
| 숫자 1 | HUD 조작 커서 열기/닫기. 패널이 닫혀 있으면 함께 펼친다. 커서가 열려 있는 동안 이동·시점 입력을 막고 사격·ADS를 해제한다. |
| 실험 설정 / 통계 보기 | 같은 오른쪽 패널에서 조건 조절 화면과 실시간 수치·그래프 화면 전환 |
| 끄기 / 켜기 또는 F6 | 서버 리와인드 끄기/켜기 |
| 0 / 50 / 100 / 150 / 200 / 500 또는 F7 | 추가 패킷 지연 선택. F7은 이 여섯 값을 순환한다. |
| 지연 −50 / +50 | 편도 0~1,000ms를 50ms 단위로 조절. 예: 250, 350, 550ms도 가능 |
| 초기화 또는 F8 | 현재 조건을 유지하면서 세션 전체의 측정 구간을 새로 시작한다. |

상세 패널을 접어도 통계 수집은 계속하며 조건과 표본을 초기화하지 않는다. Tab으로 관찰용 패널만 펼칠 때는 마우스 조준을 유지한다. Tab으로 접으면 커서도 닫고 이동·시점을 돌려준다. 슬라이드 중에는 버튼을 누를 수 없다.

지연 값은 각 송신 방향에 추가하는 밀리초다. 100을 선택하면 서버→클라이언트 100ms와 클라이언트→서버 100ms가 추가되어 RTT는 약 200ms 증가한다. 실제 RTT에는 전송 주기와 처리 시간이 더해진다. 실험 프리셋은 패킷 손실·지터·복제·순서 변경을 0으로 맞춘다. Standalone에는 네트워크 연결이 없으므로 지연 비교는 2인 PIE `Play As Client` 또는 독립 서버/클라이언트로 진행한다.

500ms는 편도이며 추가 RTT는 약 1,000ms다. 네트워크 설정만 조절하며 리와인드 이력·허용 시간은 자동으로 늘리지 않는다. 큰 지연에서 시각 범위 초과나 이력 부족으로 요청이 거절될 수 있고, 거절도 응답 통계에 포함된다.

## HUD에서 자동 실험

`1`로 커서를 열고 상단 **실험 설정**을 선택한다. 모든 설정은 서버 승인 후 세션에 복제된다.

| 옵션 | 적용 범위 |
|---|---|
| 기준 지연 | 리와인드 끄기, 정지 표적, 3회 반복을 기본 선택. 이후 표적·반복을 수정할 수 있다. |
| 보정 비교 | 이동 표적, 1회 반복을 기본 선택. 각 반복에 리와인드 끄기 → 켜기 두 구간을 실행한다. |
| 정지 / 이동 | 실제 상대 캐릭터의 정지 또는 좌우 사인 이동. 이동은 진폭 240cm, 주기 2.4초다. |
| 의도적 빗맞힘 끄기 / 켜기 | 기본 꺼짐. 보정 비교에서 켠 경우에만 매 네 번째 발사를 표적보다 3m 위로 조준한다. 실험 종류를 다시 선택하면 꺼짐으로 돌아간다. |
| 거리 − / + | 5~30m, 1m 단위. 두 캐릭터를 선택한 거리로 배치한다. |
| 발사 수 − / + | 구간당 1~60발, 1발 단위. 30발을 넘으면 기존 재장전을 거쳐 계속한다. |
| 반복 − / + | 모드당 1~5회. 보정 비교에서 24발 × 3회이면 두 모드 합계 144발이다. |
| 실험 시작 / 중지 | 시작을 요청한 플레이어가 자동 조준·사격을 담당한다. 진행 중 조건 변경은 막으며 중지 후 변경한다. |

서로 다른 팀의 생존한 플레이어 두 명과 정상 무기가 필요하다. 실행 시 플레이어의 위치·시선·이동 모드·체력·방어구·탄약을 보관한다. 실험 동안 두 플레이어의 수동 이동·조준·사격을 막고 임시 체력을 사용한다. 구간마다 탄약을 준비하고, 조건 안정화 후 최소 0.65초 간격으로 서버 응답을 기다리며 발사한다. 기본 조준점은 계속 표적 중심이다. 위로 조준하는 동작은 보정 비교의 **의도적 빗맞힘** 옵션을 명시적으로 켰을 때만 사용한다. 종료·중지 후 지연 중인 요청이 지나갈 시간을 기다린 다음 원래 상태로 복구한다. 접속 종료·사망·응답 시간 초과도 중지 경로로 처리하며 사망한 캐릭터를 되살리지 않는다.

설정 화면에는 진행 구간·발사 수와 끄기/켜기의 실제 명중 수가 표시된다. 통계 화면의 현재·평균·최소·최대는 그 창의 현재 구간 기준이다. 패널을 접어도 자동 실험은 계속하고 요약 카드에 진행 상태가 남는다. 모든 구간의 발사·응답·실제 명중·거절은 서버 로그의 `[LiveScenario] SAMPLE`에 남는다.

이 기능은 플레이 중 조건을 바꾸는 현장 실험이다. 기존 PPT의 360발/240발 원시 자료를 자동 재현하거나 덮어쓰지 않는다. 기존 명령줄 벤치마크는 유지하며, 새 실험은 기존 무기의 서버 탄 퍼짐 순서를 계속 사용한다. 따라서 여기의 `명중 수/발사 수`를 기존 보고서의 `예상 명중 복원율`과 같은 지표로 해석하지 않는다. 현재 맵의 엄폐물·무기 탄 퍼짐도 실제 명중에 영향을 준다.

## 지표와 표본

| HUD 행 | 의미 | 집계 시점 |
|---|---|---|
| 왕복(ms) | 시각 동기화의 왕복 시간. 초기 동기화 전에는 플레이어 Ping을 사용하며, 아직 측정되지 않은 네트워크 세션의 초기 0은 집계하지 않는다. | 0.05초마다 |
| 프레임/초 | 프레임 DeltaTime의 역수 | 매 프레임 |
| 프레임(ms) | 실제 프레임 DeltaTime. 순간적인 느린 프레임도 극값에 포함한다. | 매 프레임 |
| 응답(ms) | 로컬 발사 요청부터 해당 요청의 신뢰성 있는 서버 결과 응답까지의 단조 시계 경과 시간 | 정상 대응된 결과 응답마다, 승인·거절 모두 포함 |
| 발사경과(ms) | 서버가 계산한 발사 시각의 경과 시간 | 승인된 발사마다 |
| 되감기(ms) | 서버가 사용한 표적 되감기 시간. 리와인드를 끄면 0이다. | 승인된 발사마다 |

`현재`는 마지막 유효 표본, `평균`는 현재 구간 전체 표본의 산술평균, `최소/최대`는 전체 구간의 극값이다. FPS 평균도 각 프레임 FPS 표본의 산술평균이며 전체 프레임 수/시간으로 계산한 처리량 FPS와는 정의가 다르다. 표본이 없으면 `--`를 표시한다. `통신`, `응답`, `승인` 표본 수으로 해당 집계의 표본 수를 확인한다. 아래 그래프는 최근 네트워크 120개와 사격 20개만 표시하지만 평균·최소·최대는 이전 표본도 계속 포함한다.

조건을 변경하면 `측정 구간`가 증가하며 통계와 그래프를 비운다. `서버 설정 적용 중`은 서버 승인·복제를 기다리는 상태, `안정화 중`은 이전 지연 패킷을 비우고 새 시계 표본을 기다리는 상태다. 워밍업은 서버 기준 2~2.8초, 각 클라이언트의 조건 수신 후 최소 1.5초이며 둘 다 지나야 수집한다. 이 동안에도 게임과 사격은 계속 진행되지만 측정 표본에는 포함하지 않는다. `측정 중`부터 새 표본을 집계한다.

서버 결과에는 실제 처리한 실험 revision을 포함한다. 이전 조건의 지연 응답, 무기 교체 전 응답, 중복 응답, 요청과 대응되지 않는 응답은 새 통계에 포함하지 않는다. 리스폰은 현재 실험 통계를 유지하며 새 무기의 사격 이벤트만 다시 연결한다. 런타임 실험 설정은 데이터 에셋이나 INI에 저장하지 않는다.

## 검증 재실행

```powershell
# UE 5.7 Editor 타깃 빌드 후, 서버 1개와 클라이언트 2개로 10개 조건과 초기화 검사
.\Tools\Start-FPSBaseline.ps1 -LiveExperimentCheck

# 동일 검사와 실제 HUD 캡처. 숨겨진 창에서 렌더링한다.
.\Tools\Start-FPSBaseline.ps1 -LiveExperimentCheck -CaptureFrames

# HUD 시나리오: 정지 표적 반복 → 빗맞힘 꺼짐/켜짐 각각 보정 비교 → 편도 500ms
.\Tools\Start-FPSBaseline.ps1 -ScenarioCheck -CaptureFrames
```

각 프로세스 로그는 `Saved/FPSBaseline/*-live-experiment/`, HUD 캡처는 `Saved/LiveExperiments/Condition-*.png`에 저장된다. `LiveExperimentCheck`의 양쪽 클라이언트 PASS와 서버/클라이언트의 실제 `DriverLagMs`를 확인한다. C++ 자동화의 `LatencyCombat.Experiment`는 집계·조건 경계·HUD/키보드 명령을 검사한다.

2026-10-30 시나리오 HUD 검증에서는 Editor 및 Game Development 빌드가 성공했고 `LatencyCombat` 자동화 35개가 성공했다. `Saved/Codex/ScenarioHUD/CompletedAutomation/`에 설정 범위, HUD 증감, 중복 요청, 취소·복구·재진입, 참여 캐릭터 파괴와 모드별 반복 집계 결과를 보관한다.

별도 서버와 D3D12 클라이언트 두 개에서 정지 표적 10m·100ms·3발×2회, 이동 표적 18m·150ms·끄기/켜기 각 4발, 정지 표적 25m·500ms·2발을 실행했다. 양쪽 클라이언트가 세 시나리오를 완료했다. 로그는 `Saved/FPSBaseline/20261030-003628-514-0ms-scenario/`, 화면은 `Saved/LiveExperiments/Scenario-Shooter.png` 및 `Scenario-Observer.png`에 있다. 자동 실행으로 확인한 동작이며 물리 마우스로 모든 옵션을 직접 클릭한 수동 플레이 검증과 구분한다.

의도적 빗맞힘 분리 후에는 자동화 36개가 성공했다. 실제 자동 사격을 실행해 기본 설정에서 모든 발사가 표적을 조준하고, 켠 경우에만 각 구간의 네 번째 사격이 위를 향하며 실제로 빗맞는지 검사했다. 결과는 `Saved/Codex/ScenarioHUD/MissOptionAutomation/`에 있다. 두 D3D12 클라이언트에서도 옵션 꺼짐/켜짐을 포함한 네 시나리오가 모두 완료됐고, 실제 발사 방향 16개를 대조했다. 로그는 `Saved/FPSBaseline/20261030-004919-256-0ms-scenario/`, 상세 확인 자료는 `Saved/Codex/ScenarioHUD/MissOptionVerification.json`이다. 888×500 설정 화면의 `Scenario-MissOff-Shooter.png`와 `Scenario-MissOn-Shooter.png`도 `Saved/LiveExperiments/`에 저장한다.
