# 공격 Prediction / Reconciliation 설계 (M2)

현재 단계는 Baseline 계측 및 후속 구현 설계다. 실제 공격 Prediction / Reconciliation은 아직 적용하지 않았다. 이동은 Unreal CharacterMovement의 기존 네트워크 처리 경로를 사용한다.

## 현재 호출 흐름

`CombatInputComponent → CombatWeapon.Fire::FireWeapon → Fire::ServerFire(FCombatShotCommand) → 서버 시각·순서·생명 검증 → HitValidation / ApplyDamage → MulticastShot / Reliable ClientShotResult / Health 복제`.

사격 효과는 서버 승인 이후 재생한다. 명중·승인·거절 결과는 6주차의 Reliable `ClientShotResult`로 전달하고, 표현 multicast는 Unreliable을 유지한다. 후속 승인 대기 목록·보정 프로토콜은 Fire 컴포넌트와 Ammo 상태를 기준으로 구현한다.

클라이언트는 조준 의도와 발사 식별자를 전달한다. 발사 위치, 대상, 피해량, 탄약, 사망, 점수는 서버에서 결정한다. `ShotId`와 생명 ID는 계측 대응과 서버의 중복·순서 검증에 함께 사용한다. 현재 명령에는 검증 대상 서버 발사 시각도 포함한다. 사격 효과와 명중 확인은 승인된 서버 응답 뒤에 실행되므로 지연에 따른 반응 시간 차이가 생긴다.

## 먼저 구현할 범위

| 항목 | 클라이언트 즉시 처리 | 서버 결정 / 보정 |
|---|---|---|
| 사격 효과 | 로컬 총구 효과, 소리, 반동 | 다른 플레이어에게 승인된 효과 전달 |
| 화면 탄약 | 승인 대기 요청을 반영한 표시용 탄약 | 실제 탄약, 마지막 처리 요청 번호 |
| 발사 가능 여부 | 최근 승인 상태와 대기 요청으로 임시 판단 | 발사 간격, 재장전, 사망, 경기 종료 검사 |
| 명중 | 조준 피드백만 처리 | 실제 hitscan, 피해량, HP, 명중 확인 |
| 재장전 | 후속 범위로 분리 | 우선 기존 서버 재장전 유지 |

HP·킬·팀 점수와 타격 판정은 예측하지 않는다. 첫 범위는 로컬 사격 체감과 표시용 탄약으로 제한한다. 과거 위치를 복원하는 Lag Compensation은 6주차에 별도 컴포넌트로 구현했다. 로컬 효과·탄약 예측은 이 문서의 후속 범위다.

## 요청과 승인 모델

1. 소유 클라이언트가 생명 주기 식별자와 증가하는 요청 번호를 발급한다. 요청에 조준 의도와 로컬 표시 시간(진단용)을 넣고 승인 대기 목록에 보관한다.
2. 로컬 효과를 한 번 실행하고 표시용 탄약을 차감한다. 실제 `MagazineAmmo` 복제 값을 클라이언트에서 수정하지 않는다.
3. 서버는 캐릭터 소유권과 생명 주기, 중복·순서, 유한한 조준 값, 발사 간격, 탄약, 재장전, 사망, 경기 상태를 검사한다. 승인된 경우에만 기존 서버 hitscan과 탄약 차감을 수행한다.
4. 소유 클라이언트에 신뢰성 있는 승인/거절 응답을 보낸다. 응답에는 마지막 처리 요청 번호, 실제 탄약, 전투 상태, 거절 이유와 생명 주기를 포함한다. 현재 Reliable `ClientShotResult`는 승인·거절 이유와 계측 결과를 전달한다. 예측 구현 시에는 여기에 탄약·상태·생명 스냅샷을 추가해야 한다.
5. 응답 수신 시 처리된 요청을 대기 목록에서 제거하고, 서버 스냅샷 위에 아직 승인되지 않은 요청을 순서대로 재적용해 표시용 탄약을 만든다. 이때 효과나 소리를 다시 실행하지 않는다.
6. 서버가 돌려준 사격 효과는 소유 클라이언트에서 요청 번호로 중복 제거하고, 다른 클라이언트는 승인된 효과를 재생한다. 명중 표시도 서버 승인 뒤에만 켠다.

독립 복제된 탄약과 RPC의 도착 순서를 가정하지 않는다. 승인 스냅샷에 요청 번호와 상태를 함께 넣어 기준을 정하고, 그보다 오래된 응답은 무시한다. 사망·리스폰·무기 교체 시 대기 목록을 비우고 새 생명 주기를 사용한다. 시간 제한이나 대기 목록 상한을 넘으면 예측을 일시 중단하고 서버 상태를 기준으로 복구한다.

## 검증 기준

- 0/50/100/150/200ms에서 입력→로컬 효과는 네트워크 왕복을 기다리지 않아야 한다. 현재 Baseline의 서버 효과 응답 지연과 같은 시작 지점으로 비교한다.
- 정상 승인, 발사 간격 거절, 재장전 중 발사, 빈 탄창, 사망 직전 발사, 경기 종료, 중복·오래된 요청을 확인한다.
- 여러 요청이 동시에 승인 대기 중일 때 일부가 거절돼도 표시용 탄약이 서버 값으로 수렴해야 한다.
- 효과가 두 번 재생되지 않고, 다른 플레이어와 HP·점수는 기존 서버 결과를 유지해야 한다.
- 순서 변경, 지터, 손실 조건은 별도 실험으로 추가한다. 이번 Baseline 측정은 지터·손실 0이며 순차 단발이므로 이 조건들을 검증했다고 볼 수 없다.
